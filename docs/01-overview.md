# 설계문서 1/5 — 개요 · 목표 · 사용자 · 제어 방식

> 목차와 구현 기록(§15)은 [../agent.md](../agent.md). 이 파일은 원문 §1~§4 그대로이며, v3.0 에서 바뀐 곳만 표시했다.

## 1. 개요

- **한 줄 요약**: 가족이 쓰는 공기계(갤럭시 S20 이상)에 설치해, 특정 앱들을 차단 목록에 넣고 정해진 시간대에만 열리게 하며, 앱 실행 이력을 날짜별로 남겨 관리자가 확인할 수 있게 하는 앱.
- **플랫폼**: 안드로이드 전용 (**Android 13 / API 33 이상**)
- **사용자**: 가족 (설정 = 관리자 / 사용 = 공기계를 쓰는 가족 구성원)
- **배포**: APK 수동 배포
- **성격**: **소프트 가드** — 우회를 막는 도구가 아니라, 정해둔 규칙을 기기가 지켜주는 도구 (§2.3)

### 정책 한 줄 요약

```
차단 목록에 넣은 앱  →  기본 차단, 공통 허용 시간대에만 열림
차단 목록에 없는 앱  →  항상 허용 (시스템 앱 포함)
모든 앱 실행 이력    →  로컬에 180일 보관, 날짜별 조회, 관리자만
제어가 꺼졌던 구간    →  이력에 "기록 공백"으로 표시
```

### 확정 사항

| 항목 | 결정 |
| --- | --- |
| 대상 기기 | 갤럭시 S20 이상 |
| 최소 SDK | **API 33 (Android 13)** |
| 제어 방식 | 접근성 서비스 + 오버레이 (Device Owner 미사용, ADB·초기화 불필요) |
| 정책 기본값 | **블랙리스트** — 전부 허용, 차단할 앱만 지정 |
| 시간 규칙 | **차단 목록 전용 공통 허용 시간대** (요일 + 시작~종료) |
| 인증 | **6자리 숫자 PIN 하나** |
| 실행 이력 | **모든 앱 · 로컬 저장 · 180일 보관 · 날짜별 조회** |
| 이력 중복 억제 | **10초** |
| 제어 중단 구간 | **이력에 기록 (GUARD_STARTED / GUARD_STOPPED)** |
| 설정 앱 | 차단하지 않음 |
| 삭제 방지 | 하지 않음 |
| 서버 | 없음. 전부 로컬 |
| **1차 제외** | 임시 허용 요청 · 앱별 집계 화면 · 제어 일시 중지 · CSV 내보내기 (§13) |

## 2. 목표와 비목표

### 2.1 목표
- 차단 목록의 앱이 전면에 올라오면 즉시 차단하고 이유를 보여준다
- 차단 목록의 앱은 정해진 시간대에만 열린다
- 모든 앱의 실행 이력을 남기고, 관리자가 날짜를 골라 조회할 수 있다
- 제어가 꺼져 있던 구간을 이력에서 구분할 수 있다
- 부팅 후 별도 조작 없이 계속 동작한다
- 평상시 배터리·메모리 사용량이 무시할 수준이다
- PIN을 모르면 정책과 이력을 볼 수도, 바꿀 수도 없다

### 2.2 비목표
- iOS 지원 / 플레이스토어 배포
- 위치 추적, 메시지·화면 내용 열람
- 서버 연동 / 원격 설정 변경 / 이력 외부 전송
- 우회 방지 및 삭제 방지

### 2.3 설계 전제 — 이 앱이 막지 못하는 것 (명시)

| 경로 | 비고 |
| --- | --- |
| 설정 → 접근성 → 이 앱 끄기 | 약 15초. 설정 앱을 허용하기로 했으므로 열려 있음. **단 이력에 흔적이 남는다** (§8.7) |
| 앱 삭제 | 즉시 가능. 삭제 방지 미적용. **이력도 함께 사라진다** |
| 안전 모드 부팅 | 접근성 서비스 미로드 (제어·기록 모두 중단, 이력에 공백으로 남음) |
| 기기 시각 변경으로 허용 구간 만들기 | 가능 |
| 삼성 Secure Folder / 게스트 사용자 | 별도 프로필이라 접근성 서비스가 적용되지 않음 |
| 새로 설치한 앱 | 블랙리스트이므로 자동 허용 → §7.1 대응 |
| 브라우저로 같은 서비스 접속 | 유튜브 앱을 막아도 브라우저로 접속 가능 → §7.1 대응 |

> 이는 결함이 아니라 선택이다. 그 대가로 필요 권한이 2종으로 줄고, 설치 절차가 짧아지고, 앱이 오작동해도 기기가 잠기지 않는다.
> 다만 **꺼진 사실 자체는 이력에 남으므로**, "막지는 못해도 알 수는 있다".

## 3. 사용자와 시나리오

| 역할 | 하는 일 |
| --- | --- |
| **관리자** | 앱 진입(PIN) → 차단할 앱 선정 → 공통 허용 시간대 설정 → 날짜별 실행 이력 확인 |
| **사용자** | 공기계 사용. 차단 목록 앱은 허용 시간에만 열림. 나머지는 자유 |

**흐름**
1. 관리자가 APK 설치 → 초기 설정 (PIN → 권한 → 차단 앱 → 허용 시간대)
2. 재부팅 → 접근성 서비스 자동 복구 → 정책·기록 계속 동작
3. 사용자가 차단 앱 실행 → 허용 시간이 아니면 안내 화면이 덮음
4. 관리자가 필요 시 PIN으로 들어가 날짜를 골라 이력 확인 및 정책 조정

## 4. 제어 방식 — 접근성 서비스

### 4.1 동작 원리

```
사용자가 앱 아이콘 탭
        ↓
안드로이드가 접근성 이벤트 발생 (TYPE_WINDOW_STATE_CHANGED)
        ↓
[SoftGuardAccessibilityService]
   event.packageName = "com.google.android.youtube"
        ├─→ PolicyEngine.evaluate(pkg, now())  →  Blocked
        │       ↓
        │   오버레이 표시 "지금은 사용 시간이 아니에요 · 19:00부터"
        │
        └─→ EventLogger.recordLaunch(pkg, now(), blocked = true, reason)
                ↓
            메모리 버퍼 → 배치로 Room DB 기록
```

### 4.2 필요 권한

| 권한 | 용도 | 획득 방법 (One UI 기준) |
| --- | --- | --- |
| **접근성 서비스** (`BIND_ACCESSIBILITY_SERVICE`) | 전면 앱 감지 | 설정 → 접근성 → 설치된 앱 → 우리집 소프트가드 → 켜기 |
| ~~다른 앱 위에 표시~~ (`SYSTEM_ALERT_WINDOW`) | ~~차단 안내 오버레이~~ | **v3.0 에서 불필요.** 오버레이를 접근성 서비스 전용 창(`TYPE_ACCESSIBILITY_OVERLAY`)으로 띄우므로 이 권한 없이 동작한다. 필요 권한은 접근성 하나다 (§15) |

부가 권한: `RECEIVE_BOOT_COMPLETED`, `QUERY_ALL_PACKAGES`(설치 앱 목록), `SCHEDULE_EXACT_ALARM`, `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`, `POST_NOTIFICATIONS`(상태 이상 알림용 — Android 13+ 런타임 요청 필수).

> **minSdk 33의 이점**: 버전 분기가 사라진다. "제한된 설정" 절차, `POST_NOTIFICATIONS` 런타임 요청, `SCHEDULE_EXACT_ALARM` 이 모두 **항상 적용**되므로 조건 분기 없이 한 경로만 구현하면 된다.
> **주의**: 공기계가 Android 12 이하라면 설치되지 않는다. One UI 5 이상으로 업데이트되어 있는지 먼저 확인할 것.

### 4.3 차단 집행 방식

| 방식 | 채택 | 비고 |
| --- | --- | --- |
| **오버레이 뷰** (`TYPE_ACCESSIBILITY_OVERLAY`) | **주 수단** | 접근성 서비스가 직접 띄우는 창. 별도 권한 불필요. 백그라운드 액티비티 실행 제한을 받지 않고, 뷰를 재사용해 빠르다 |
| `GLOBAL_ACTION_HOME` | 폴백 | 오버레이 창 생성이 예외로 실패했을 때만 (최소 간격 2초). 이유를 알려줄 수 없음 |
| 액티비티 실행 | 미채택 | 백그라운드 실행 제한에 걸릴 수 있음 |

- 차단 앱이 **0.2~0.5초 정도 보였다가 덮인다.** 접근성 이벤트 전달 지연에 따른 구조적 특성이다. 오버레이 뷰를 미리 만들어 두어 지연을 최소화한다.

### 4.4 (보류) Device Owner 승격 경로

강제력이 필요해지면 공장 초기화 + ADB 1회로 Device Owner로 승격할 수 있다. 그때를 위해 **집행 레이어를 인터페이스(`Enforcer`)로 분리**해 둔다. 정책 모델·이력·UI는 그대로 재사용된다.
