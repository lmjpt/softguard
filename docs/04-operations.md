## 9. 화면 구성

| 화면 | 내용 |
| --- | --- |
| **초기 설정 마법사** | ① PIN 등록(2회) ② 접근성 권한 (제한된 설정 해제 안내) ③ 오버레이 권한 ④ 삼성 절전 설정 3종 (§5.4) ⑤ 정확 알람 + 알림 권한 ⑥ 차단 앱 선정 (+ §7.1 추천 제안) ⑦ 허용 시간대 설정 |

| 대시보드 | **동작 상태(정상/중단)** · 지금 차단 앱 사용 가능 여부 · 다음 전환 시각 · 오늘 실행/차단 건수 · **최근 7일 제어 중단 횟수** |
| 차단 앱 설정 | 설치 앱 목록 + 검색 + 차단 토글. 시스템 핵심 앱 선택 시 경고. 자기 자신 제외 |
| 시간대 설정 | 구간 추가/삭제 (요일 다중선택 + 시작/종료). 주간 타임라인 미리보기. 비우면 "항상 차단" 안내 |
| **실행 이력** | 날짜 선택 + 요약 + 목록 + 필터 + 공백 블록 (§8.6, §8.7) |
| 차단 안내 (오버레이) | 앱 이름 + 이유별 문구 + 다음 사용 가능 시각 + 홈으로 버튼 |
| 설정 | PIN 변경 · 이력 전체 삭제 · 정책 내보내기/가져오기 · 정보(기록 항목 명시) |

## 10. 운영 고려사항

### 10.1 자체 상태 점검 (필수)

접근성 서비스가 꺼지면 제어와 기록이 **조용히** 멈춘다.

- 대시보드 최상단에 **"제어 동작 중 / 중단됨"** 을 크게 표시
- 점검 항목: 접근성 활성 여부, 오버레이 권한, 배터리 최적화 제외, 정확 알람 권한, 알림 권한
- 중단 상태면 해당 설정 화면으로 이동하는 버튼 제공
- **이력의 공백 블록**(§8.7)이 사후 확인 수단으로 함께 작동한다

### 10.2 테스트 항목

**정책 엔진 (단위 테스트)**
- 구간 시작/종료 정각, 자정 넘김, 겹치는 구간, 빈 시간대
- 판정 5단계 각 분기

**이력**
- 10초 중복 억제 동작 (같은 앱 9초/11초 후 재진입)
- 배치 flush: 10건 / 15초 / 화면 꺼짐 / 서비스 종료
- `dayKey` 계산 정확성 (자정 직전/직후, 타임존 변경 후)
- 9만 건 상태에서 날짜별 조회 성능
- 180일 정리 동작
- 앱 삭제 후에도 `appLabel` 이 남아 조회되는지

**제어 중단 구간 (§8.7)**
- 접근성 정상 끄기 → `GUARD_STOPPED(inferred=false)` → 다시 켜기 → 공백 블록 표시
- 앱 강제 종료 → `GUARD_STOPPED(inferred=true)` 추론 확인
- 기기 재부팅 → `DEVICE_BOOT` 이 공백 안에 표시되는지
- 공백이 자정을 넘길 때 두 날짜에 나뉘어 표시되는지

**기타**
- 재부팅 후 정책 유지 및 서비스 자동 복구
- 허용 시간대 종료 시각 도달 → 쫓아내기
- 차단 앱 삭제 시 목록 자동 정리 / 이력 보존
- PIN 백오프 동작
- **릴리스(R8) 빌드로 실기기 테스트** — 난독화로 서비스·리시버·Room 엔티티가 깨지는 사고 방지
- 삼성 절전 설정을 일부러 켠 상태에서 서비스 생존 확인
- 배터리·용량: 하루 방치 후 통계 확인 (M6)

## 11. 배포 (APK 수동)

> **v3.0**: APK 는 GitHub Actions 가 만들어 Release 에 올린다 (`.github/workflows/android.yml`,
> `:core:test` → `:app:assembleRelease`). 공기계는 아래 주소에서 직접 내려받는다.
> **https://github.com/lmjpt/softguard/releases/latest/download/softguard.apk**
> 서명 키 원본은 PC 의 `android-signing.local/` (git 제외), GitHub secret 세 개로 전달. 설치 절차는 README.md.

- release keystore 생성 후 **반드시 백업** (분실 시 기존 설치본 업데이트 불가) — 2026-09-18 생성, `android-signing.local/README.txt` 에 비밀번호·지문
- 공기계에서 "출처를 알 수 없는 앱 설치" 1회 허용
- **설치 절차 문서 필요** (M7 산출물): APK 설치 → 제한된 설정 허용 → 접근성 켜기 → 오버레이 허용 → 삼성 절전 설정 → 초기 설정
- ProGuard/R8 keep 규칙: `AccessibilityService`, 모든 `BroadcastReceiver`, Room 엔티티/DAO, 정책 직렬화 클래스
- `android:allowBackup="false"` — 백업/복원으로 정책·이력이 되돌아가는 것 방지
- **Room 마이그레이션 필수**. 스키마 변경 시 `Migration` 작성 — destructive migration 금지 (180일 이력이 날아간다)

## 13. 검토 항목 정리 (2026-09-17 완료)

### 13.1 결정 기록

| # | 항목 | 결정 | 근거 |
| --- | --- | --- | --- |
| 1 | 차단 이벤트 중복 억제 | **허용·차단 동일하게 10초** | 구현이 단순하고 이력이 깔끔하다. 반복 시도 정황은 포기. 오버레이 중복 이벤트로 이력이 오염되지 않는 이점도 있다 |
| 2 | 이력 앱별 집계(Top N) | **1차 제외** | 날짜별 목록으로 시작. 쓰다가 필요해지면 추가 (§13.2) |
| 3 | 제어 일시 중지 | **1차 제외** | 시간대 설정을 잠시 바꾸는 것으로 대체 가능. PAUSED 상태를 만들면 "정상/중단됨/일시중지" 상태 조합이 대시보드·이력 표시·상태 점검 전반으로 번진다 |
| 4 | 이력 CSV 내보내기 | **1차 제외** | 이력은 앱 안에서만 본다. "로컬 전용, 기기 밖으로 나가는 경로 없음"(§8.9) 원칙을 유지 |
| 5 | 개발 환경 | **미비 — 준비 필요** | 실기기 없음, Android Studio 없음, JDK는 Zulu 8만 존재(AGP 8.x는 JDK 17+ 필요). → §14 |
| 6 | 차단 앱별 개별 시간대 | **보류 (확장 여지만 확보)** | 공통 시간대 하나로 확정. 필요해지면 `allowWindows` 를 `blockedPackages` 항목 안으로 옮기는 변경이며, `PolicyEngine.evaluate()` 의 4·5단계만 수정하면 된다 |

### 13.2 향후 확장 후보 (1차 이후)

우선순위 순. 모두 현재 설계를 깨지 않고 얹을 수 있다.

| 후보 | 손대야 하는 곳 | 비용 |
| --- | --- | --- |
| 앱별 집계 화면 | `GROUP BY packageName` 쿼리 + 화면 1개 | 작음 |
| 차단 앱별 개별 시간대 | 정책 스키마 + `evaluate()` 4·5단계 + 시간대 편집 UI | 중간 |
| 제어 일시 중지 | PAUSED 상태 + 자동 복귀 알람 + 전용 이력 타입 + 상태 표시 3곳 | 중간 |
| CSV 내보내기 | Storage Access Framework + 변환 로직 | 작음 (단 §8.9 원칙과 상충) |
| 네이티브 강제력 (Device Owner) | `Enforcer` 구현체 교체 (§4.4) — 정책·이력·UI는 그대로 | 큼 (공장 초기화 + ADB 필요) |

> §4.4의 `Enforcer` 인터페이스 분리와 §13.2의 확장 경로를 미리 잡아둔 것이 이 설계의 유일한 선제 투자다. 나머지는 모두 1차 범위에 필요한 만큼만 설계했다.
